# 散场之后

个人作品集与独立匿名论坛，使用原生 HTML、CSS、JavaScript、Node.js 内置 SQLite。无第三方服务端依赖。

## 运行网站

需要 Node.js 24 或更高版本。现在已有数据库与后台，不能通过双击 HTML 使用全部功能。在本目录运行：

```sh
npm run init-admin
npm start
```

首次初始化命令在本机终端设置管理员密码，输入不会回显。也可以运行 `node init-admin.mjs --generate` 自动生成随机密码。已存在管理员时，此命令不会覆盖账号。

默认访问地址为 `http://127.0.0.1:4173`，仅限本机；端口被占用时可通过 `PORT` 设置其他端口。Windows 也可使用同目录的 `Start-Local.ps1` 隐藏启动服务。

独立页面：

- `/works`：作品集。初始没有作品，不包含虚构示例。
- `/forum`：自由论坛。访客可以直接发帖、回复，昵称选填，无需账号。
- `/about`：关于我。
- `/admin`：已有管理员登录，前台没有入口。直接访问 `/admin.html` 不提供页面。

没有用户系统、注册页、注册接口或在线创建管理员功能。管理员只有一个，在服务器本机初始化；隐藏后台入口不能替代密码验证，所有后台接口仍需验证登录。

## 管理功能

- 作品：上传封面、视频、图片、PDF；素材排序和说明；存草稿、发布、下架、删除、首页精选。
- 调色作品：在作品编辑页启用“调色对比”，分别上传调色前和调色后两份图片或视频。支持实时预览、替换、移除、拖动分界线、全屏，以及视频统一播放和进度；发布前检查文件成对、类型与画幅一致。视频需相同剪辑、帧率、时长和起始帧，浏览器会校正漂移，但不承诺逐帧精确同步。
- 论坛：隐藏与恢复帖子、置顶、关闭与开放回复、删除帖子、隐藏与删除回复。
- 站点：名称、署名、首页文字、个人介绍、联系邮箱、作品分类。
- 完整备份：登录 `/admin` 后进入“站点设置”，点击“下载完整备份”。下载包包含 `data/portfolio.sqlite`、`uploads/`、论坛帖子与回复、作品、站点设置和管理员数据；这是敏感备份，只能保存在私密位置。
- 安全：密码加盐 scrypt、HttpOnly 会话、CSRF 校验、跨站写入限制、登录和匿名发言限流、文件签名检查、非公开素材权限检查。
- 发言默认即时公开；同一来源发帖间隔至少 20 秒、每小时最多 15 条，回复间隔至少 10 秒、每小时最多 40 条。限流是防刷措施，不是账号登录要求。
- 匿名仅表示无账号：服务端会短期保存 IP 的 HMAC 摘要用于限流，事件保留最多 24 小时；不承诺无法追踪的匿名。
- 桌面和手机响应式布局、日夜模式柔和切换、键盘访问和弹窗关闭。日夜模式前后台统一，记住浏览器选择；未选择时跟随系统外观，页面首次显示前应用主题，减少白屏闪烁。支持 View Transitions 的浏览器使用淡入淡出，其他浏览器使用颜色过渡；开启系统“减少动态效果”时直接切换。
- 动效：首屏文字分层入场、影院背景轻缓归位、内容滚动显现、按钮与导航悬停反馈、弹窗淡入。尊重系统“减少动态效果”，不使用自动播放对比视频或循环干扰阅读的装饰动画。

## 后续作品

直接在聊天中提交作品文件、名称、分工和介绍，我可以接着整理并添加；资料格式见 `WORK_SUBMISSION.md`。也可以自己在 `/admin` 里维护作品。

`site.json` 仅是首次启动时的站点默认值；启动后以数据库设置为准。站名“散场之后”和署名“小影”可在后台修改。头像仍为你提供的原图；首屏影院照片仅是视觉背景，不是你的作品。

## 维护指令

源码包里已经留下固定的维护入口。以后网站代码有更新，或需要重新打包时，在本目录打开 PowerShell 执行：

```powershell
# 运行服务端测试
npm run check

# 生成不含数据库、上传作品和部署私密配置的源码包
npm run package

# 先测试，再生成源码包，适合每次网站更新后使用
npm run release

# 生成包含当前运行数据和作品文件的完整备份
# 执行前先停止网站服务，并妥善保管压缩包
npm run backup
```

也可以直接运行 `package-site.ps1` 或 `backup-site.ps1`。压缩包会生成在当前 `film-blog` 文件夹的上一级目录，并自动带时间戳。`package` 适合交付或发布源码；`backup` 会包含 `data/`、`uploads/` 和 `.env`，不要上传到公开网盘、代码仓库或发给无关人员。这里没有开放网页更新接口，网站更新应通过服务器文件维护或可信部署流程完成。

## 数据与备份

作品、帖子、回复、管理员密码哈希及站点设置保存到 `data/portfolio.sqlite`。素材在 `uploads/`。重启不会丢失数据；主题偏好在浏览器内。

备份时先停止服务，再整体备份 `data/` 与 `uploads/`，恢复时一起还原。不要把数据库、上传目录或私人管理资料提交到公开仓库。删除作品记录不会物理删除上传素材，以免误删复用素材；必要时停机后核对再清理。

## 上线说明

这是本地可运行版本，不是已经发布的公网网站。公网部署需要 Node.js 主机、持久化磁盘、HTTPS 和正确的 `APP_ORIGIN`，例如 `https://example.com`。服务器默认只绑定 `127.0.0.1`，反向代理可转发到该地址；确有需要时可配置 `HOST`。网站、作品上传和 `/admin` 最省事且最安全的部署方式，是全部由同一个 HTTPS 来源提供，例如 `https://example.com/`、`https://example.com/admin` 和相对路径 API。这样不需要开放 CORS，后台登录 Cookie 和上传请求可以正常互通。

反向代理终止 HTTPS 时，推荐设置：

```text
APP_ORIGIN=https://example.com
TRUST_PROXY=1
```

并转发原始 `Host` 或可信的 `X-Forwarded-Host`、`X-Forwarded-Proto: https` 和请求体。`APP_ORIGIN` 必须写来源本身，不要写 `/admin` 或 `/api`，也不要带额外路径。程序会优先使用它校验 `Origin` 并设置 `Secure` 登录 Cookie；配置了 `TRUST_PROXY=1` 后，没有固定 `APP_ORIGIN` 时也会识别可信代理传来的 `X-Forwarded-Host` 和 `X-Forwarded-Proto`。只有在代理可信且 Node 端口不能被公网绕过时才开启 `TRUST_PROXY`。

“不能跨站提交”是 CSRF 安全策略，不是网站上传的法律规定。它会拒绝来自其他来源的写入请求，保护登录后台、作品上传和论坛发言。如果把前台或后台拆到另一个域名，不能只加一个 CORS 通配符；需要明确的来源白名单、凭据策略和 `SameSite=None; Secure` Cookie，并同步改前端 API 地址。除非确有跨域架构需求，否则建议保持同源路径部署，不开放任意跨站上传。

只有管理员忘记密码时，才在服务器本机重新运行 `node init-admin.mjs`；已有管理员时该命令不会覆盖密码。正式上线前应保管初始化时生成的私人密码资料。若密码和资料都遗失，没有在线重置入口，需要停机后按服务器管理员流程备份 `data/portfolio.sqlite` 与 `uploads/`，再由可信维护者执行密码恢复方案，不能通过公开网页绕过登录。

上传大小、请求超时和持久化目录也应在代理端同步设置。开放论坛上线前应配置监控、备份、内容规则、隐私说明；基础限流不能完全阻止垃圾信息。

运行测试：`npm test`。服务端支持视频 Range 请求；浏览器可用 Node 内置测试之外的 Playwright 工具验证。
